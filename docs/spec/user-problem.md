# 用户画像及问题定义

## 1. 用户与问题定义

「失恋阵线联盟」服务的是处在失恋后不同阶段的人。用户的共同问题不是单纯缺少建议，而是在情绪波动、关系复盘、社交断裂和生活重建之间缺少稳定、克制、可随时进入的支持系统。

## 2.1 核心用户画像

### 用户 A：刚分手，情绪急性期

- 状态：哭、失眠、想联系前任、脑子停不下来。
- 需求：有人立刻接住自己，不想被说教。
- 风险：深夜崩溃、冲动挽回、自责、自伤想法。
- 产品重点：即时情绪支持、冲动缓冲、陪伴式对话、安全提醒。

### 用户 B：分手 1-8 周，反复复盘期

- 状态：不断想“为什么会这样”“是不是我不够好”“还能不能复合”。
- 需求：客观分析关系，理解分手原因，获得下一步建议。
- 风险：过度沉迷复盘、被伪咨询误导、不断窥探前任。
- 产品重点：关系复盘、决策指导、认知重构、行动计划。

### 用户 C：分手后社交断裂，孤独期

- 状态：朋友听腻了，自己不敢再打扰别人。
- 需求：找到同路人，看到别人也在经历类似阶段。
- 风险：沉浸负面情绪、互相强化痛苦。
- 产品重点：同伴社群、故事分享、正向互动、阶段性打卡。

### 用户 D：想重新生活的人，重建期

- 状态：情绪开始稳定，但生活失序、自我价值感低。
- 需求：重新建立作息、兴趣、自信、社交和目标。
- 风险：空虚、复燃、重新陷入前任动态。
- 产品重点：生活秩序构建、自我效能恢复、成长任务、进度记录。

## 2.2 用户核心痛点

1. 没有人随时可听自己倾诉。
2. 朋友给的建议不稳定，容易变成“别想了”“你值得更好的”。
3. 用户想知道“我到底该不该复合/断联/发消息”。
4. 用户需要情绪出口，但又害怕打扰别人。
5. 失恋后生活节奏被打乱，不知道每天该做什么。
6. 用户需要归属感：有人懂我，而且我不是唯一一个这样的人。
7. 用户在深夜或冲动时需要被安全地拦住。

## 2.3 用户核心任务

- 我现在很痛苦，需要立刻有人陪我。
- 我想倾诉这段关系发生了什么。
- 我想知道我该不该联系 TA。
- 我想客观复盘分手原因。
- 我想找到和我一样的人。
- 我想每天做一点事，让自己慢慢好起来。
- 我想知道自己有没有变好。

## 产品设计含义

- Agent 不能只给建议，必须先承接情绪，再给具体、克制的下一步。
- 社群内容需要避免互相放大痛苦，应鼓励复盘、支持和行动。
- 发布与回应应优先支持“倾诉、复盘、求建议”三类表达。
- 后续功能应补齐冲动缓冲、断联决策、生活打卡和恢复进度记录。
- 安全边界必须持续可见，高风险表达不能被当作普通情绪处理。
