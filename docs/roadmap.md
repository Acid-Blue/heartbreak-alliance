# 长期规划

最后更新：2026-05-11

## 规划原则

长期规划以 `docs/spec/user-problem.md` 中的用户画像为输入，但不把所有需求一次性塞进 MVP。当前 MVP 负责验证“阵线小队 + 发布 + 回应 + Agent 陪伴 + 本地持久化”的基础闭环；后续迭代按用户阶段逐步补齐急性支持、关系复盘、同伴社群和生活重建。

所有阶段都必须遵守产品边界：不做医疗诊断，不替代心理咨询或危机干预，不承诺挽回关系或保证疗愈结果。

## 阶段 0：MVP 基础闭环

目标用户：A、B、C、D 的共同低门槛入口。

当前状态：已完成。

核心能力：

- 首页、互助会、Agent、我的四个 Tab。
- 阵线小队列表、小队详情、公开内容流。
- 发布倾诉、复盘、求建议内容。
- 帖子回应和本地回应数刷新。
- Agent mock 对话和本地持久化。
- 非医疗/非心理咨询服务边界提示。

## 阶段 1：急性期支持与安全边界

目标用户：用户 A，刚分手、情绪急性期。

目标：在用户深夜崩溃、想联系前任或情绪强烈时，提供即时、克制、可执行的缓冲，而不是说教或强建议。

核心能力：

- “我现在很难受”快捷入口，直接进入 Agent 或急性期支持流程。
- 冲动联系缓冲：先记录想发的话，延迟发送建议，给出 10 分钟替代行动。
- 高风险表达安全提示：当用户提到自伤、伤害他人或无法保证安全时，展示紧急求助引导。
- 深夜模式文案：降低刺激，优先提供陪伴、呼吸、短句记录和求助提醒。
- Agent 回复规范：先承接感受，再给一个小问题和一个下一步动作。

验收重点：

- 用户可以在 2 次点击内进入即时支持。
- 高风险提示清晰可见，不把危机表达当普通倾诉处理。
- Agent 不做诊断、不命令用户、不承诺结果。

## 阶段 2：关系复盘与断联决策

目标用户：用户 B，分手 1-8 周、反复复盘期。

目标：帮助用户把“为什么会这样”“该不该联系 TA”拆成具体信息和可执行决策，避免沉迷复盘或被伪咨询误导。

核心能力：

- 结构化关系复盘：事件、触发点、双方需求、反复模式、未解决问题。
- “要不要联系 TA”决策辅助：区分冲动联系、必要沟通、边界确认和不建议联系的场景。
- 断联计划：设定断联天数、替代动作、复燃提醒和复盘记录。
- Agent 上下文构造：真实读取用户发布、回应和小队公开内容摘要。
- 行动计划：把复盘结论转成 1-3 个小任务，而不是停留在分析。

验收重点：

- 用户能完成一份结构化复盘。
- 决策建议以风险、边界和替代行动呈现，不替用户做绝对判断。
- Agent 能引用用户授权范围内的上下文。

## 阶段 3：同伴社群与正向互动

目标用户：用户 C，社交断裂、孤独期。

目标：让用户看到“不是只有我这样”，同时避免社群互相强化痛苦。

核心能力：

- 小队加入/退出和阶段标签：急性期、复盘期、孤独期、重建期。
- 故事分享模板：发生了什么、我现在卡在哪里、我希望得到什么回应。
- 正向回应引导：鼓励具体支持、经验分享和行动建议，减少攻击、窥探和煽动。
- 阶段性打卡：今天守住了什么、做了一件什么小事。
- 内容治理基础：举报、隐藏、敏感词提示、运营审核入口。

验收重点：

- 用户能找到和当前阶段匹配的小队。
- 回应质量偏向支持和行动，而不是单纯共沉溺。
- 不适合公开传播的内容有基础处理入口。

## 阶段 4：生活重建与进度记录

目标用户：用户 D，情绪趋稳但生活失序、价值感低。

目标：从“处理前任关系”过渡到“重新生活”，帮助用户建立作息、兴趣、自信、社交和目标。

核心能力：

- 重建任务：睡眠、饮食、运动、整理、兴趣、社交、工作学习。
- 每日小步计划：当天只选 1-3 个可完成动作。
- 恢复进度记录：情绪波动、联系冲动、完成任务、复盘次数。
- 复燃处理：当用户重新陷入前任动态时，引导回到计划和支持系统。
- 阶段回顾：每周看到自己完成了什么，而不是只看情绪有没有消失。

验收重点：

- 用户能持续记录并看到趋势。
- 产品反馈强调自我效能，不制造“必须马上好起来”的压力。
- 重建任务能和 Agent 对话、我的页形成闭环。

## 阶段 5：真实数据、真实 AI 与治理基础设施

目标用户：全部用户。

目标：把 mock MVP 升级为可持续运营的真实产品能力。

核心能力：

- 云开发和数据库：用户、阵线小队、帖子、回应、Agent 消息、用户设置。
- 登录与隐私授权：明确 Agent 可参考的数据范围，允许用户修改授权。
- 真实 AI 接入：保留 mock 模式，新增上下文摘要、提示词边界、安全策略和日志。
- 内容安全：高风险表达识别、内容审核、举报处理、运营后台。
- 工程质量：服务层测试、自动化回归、CI、数据迁移方案。

验收重点：

- 页面层不直接依赖云数据库，仍通过 `services/` 接口访问数据。
- 用户授权范围可解释、可修改、可撤回。
- AI 回复可追踪、可回退、可被安全策略拦截。

## 优先级建议

近期优先顺序：

1. Agent 权限设置和真实上下文构造。
2. 急性期支持入口和冲动联系缓冲。
3. 小队加入/退出和阶段标签。
4. 结构化关系复盘和断联决策辅助。
5. 每日打卡和恢复进度记录。
6. 云开发、真实 AI 和内容治理基础设施。

优先级理由：先解决最高频、最高风险的“此刻需要被接住”和“我要不要联系 TA”，再扩展社群和生活重建；真实 AI 和云端能力应在产品边界、上下文结构、安全策略明确后接入。
